# Интеграционные тесты веб-консоли

Сквозные тесты менеджерской консоли: нормализация телефонов, изоляция баз,
аутентификация, зеркалирование переписки, перехват диалога, ответ менеджера,
плюс регрессия существующих эндпоинтов.

## Как запускать

Тесты работают **против живого стека** — это не unit-тесты. Нужен поднятый
`docker compose` с включённым `WHATSAPP_DRY_RUN=true` в `.env`, иначе
исходящие сообщения будут уходить реальным клиентам в WhatsApp.

Запускаются **внутри контейнера** `api`: так они видят и API на `localhost:8000`,
и базу переписки, и нет проблем с кодировкой кириллицы в Windows-терминале.

```bash
docker compose exec -T api python - < tests/integration/test_console.py
```

Весь набор по порядку:

```bash
for f in test_console test_console2 test_console3 test_system test_fixes test_unread; do
  docker compose exec -T api python - < "tests/integration/$f.py"
done
```

Ожидаемый результат — 172 PASS, 0 FAIL.

## Что в каком файле

| Файл | Покрывает |
|---|---|
| `test_console.py` | нормализация телефонов, изоляция `ChatBase`/`Base`, вход, JWT (подпись, срок), смена пароля |
| `test_console2.py` | ограничение перебора пароля, запись входящих/исходящих, идемпотентность по `wamid`, типы сообщений (фото, документ, кнопка) |
| `test_console3.py` | `GET /chats` (поиск, фильтры, пагинация), курсоры `after_id`/`before_id`, перехват, конфликт 409, гейт бота, ответ менеджера, возврат боту |
| `test_system.py` | системные сообщения при перехвате/возврате, регрессия `/products`, `/suppliers`, `/status_DB`, вебхука, раздача консоли |
| `test_fixes.py` | текст ошибки логина, фильтр `mine` по конкретному менеджеру, заголовки кеширования |
| `test_unread.py` | счётчик непрочитанных изолированно |

## Важно

- **Тесты изменяют данные** в базе `gq_chat`: чистят чаты, пересоздают их,
  сбрасывают пароли менеджеров на `TestPass_<code>_123` (кроме `kalbaeva` —
  `NewPass_kalbaeva_456`). Не запускать на проде.
- `test_console2.py` расходует лимит попыток входа для `dolakov` (5 за 15 минут).
  Счётчик живёт в памяти процесса, поэтому повторный запуск подряд упрётся в 429 —
  между прогонами нужен `docker compose restart api`.
- Не открывайте консоль в браузере во время прогона: она опрашивает API и сама
  вызывает `/read`, что сбивает проверки счётчика непрочитанных.
